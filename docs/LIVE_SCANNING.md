# Live scanning: architecture, limits and deployment

The public website (`https://eyadstein.github.io/leaklens/`) is a static
GitHub Pages build. GitHub Pages cannot execute Python, so the site contains a
**prerecorded** demo and a separate **live scan** page (`docs/live.html`).

The live page never replays recorded output and never fabricates a finding. It
only renders findings returned over HTTP by a real
`leaklens.public_api:app` backend that you configure. When no backend is
configured, the page stays in an explicit “No backend connected” state.

> **Deployment status:** the repository ships the hardened backend, a Docker
> image, a Render Blueprint, tests and this document, but **no public backend is
> deployed by this project**. The hosted page is disconnected until someone
> deploys the service and supplies its URL. Nothing in the repository or the
> website claims otherwise.

## Architecture

```
GitHub Pages (static)                     Optional free backend
┌─────────────────────────┐   HTTPS      ┌──────────────────────────────┐
│ docs/live.html          │ ───────────▶ │ leaklens.public_api:app      │
│ docs/assets/live.js     │              │ FastAPI, 1 uvicorn worker    │
│ docs/assets/live-engine │ ◀─────────── │ real LeakLens detectors      │
└─────────────────────────┘   JSON       │ in-memory uploads only       │
        │                                └──────────────────────────────┘
        │ no backend configured
        ▼
docs/demo.html (prerecorded fixtures, clearly labelled)
```

The public app is intentionally **separate** from the legacy developer API
(`leaklens.api`). The legacy app includes a pickle-based `/predict` endpoint;
the public app exposes no prediction endpoint, no model loading and no
arbitrary file access.

### Endpoints

| Method | Path | Purpose |
|---|---|---|
| `GET` | `/` | Service name and links |
| `GET` | `/health` | Liveness, version and `live: true` |
| `GET` | `/capabilities` | Real limits, enabled formats, checks, privacy statement |
| `POST` | `/inspect` | Multipart dataset; returns bounded columns and preview |
| `POST` | `/audit` | Multipart dataset, `target`, optional `test`, `group`, `time`, `threshold` |
| `POST` | `/scan` | JSON `{"source": "...", "name": "snippet.py"}` for Python code |

All responses are JSON. Errors use a stable envelope:

```json
{"error": {"code": "unknown_target", "message": "The target column was not found. Inspect the file to list its columns."}}
```

The `/audit` response contains `live`, `engine`, `trust_score`, `findings`
(severity, kind, column, evidence, fix), `counts`, `audit`, optional measured
`impact`, a bounded `summary`, and `report_html` generated by the same report
renderer the CLI uses. No metric is invented: `impact` contains measured split
statistics, not estimates of model-performance loss.

## Local run

```sh
python -m venv .venv && . .venv/bin/activate   # Windows: .venv\Scripts\Activate.ps1
pip install -e ".[api]"
uvicorn leaklens.public_api:app --host 127.0.0.1 --port 8000
```

Then either open `docs/live.html` through a local static server and enter
`http://localhost:8000`, or use the `?api=` parameter:

```
http://localhost:8000/health
http://localhost:8000/capabilities
```

Run the real-HTTP smoke test (it starts its own uvicorn subprocess and shuts it
down again):

```sh
python scripts/smoke_public_api.py
python scripts/smoke_public_api.py --url http://localhost:8000
```

The API tests use the real detectors and real HTTP multipart requests:

```sh
pytest tests/test_public_api.py tests/test_upload_guard.py -q
```

### Connecting the static page

The page accepts, in priority order:

1. `?api=https://your-service.example.com` in the URL,
2. the last URL saved in this browser’s `localStorage`,
3. `apiBase` in `docs/assets/live-config.js` (empty by default).

Only HTTPS public origins are accepted; plain HTTP is allowed only for
`localhost` / `127.0.0.1`. Credentials and query strings in the URL are
rejected. The URL is stored locally in the browser, never on LeakLens servers.

To configure the static build for a backend you operate, set `apiBase` in
`docs/assets/live-config.js` before publishing. Do **not** point the default
site at a backend you do not control: every displayed finding would then come
from that third party.

## Deployment on Render (verified free option)

Verified in November 2026 against <https://render.com/docs/free> and
<https://render.com/docs/blueprint-spec>:

* Free web service: **512 MB RAM, 0.1 CPU**.
* **750 free instance hours per month** (enough for one always-on service, but
  the service actually sleeps).
* Spins down after **15 minutes without traffic**; the next request pays a
  cold start of roughly **one minute**.
* **Ephemeral filesystem** and no persistent disk. Uploads are never written to
  disk anyway.
* Free instances are not suitable for sustained load or large datasets.

Other hosts were checked and are not free for this use case at the time of
writing: Hugging Face Docker/Gradio Spaces require a paid PRO plan (only static
Spaces are free), Fly.io has no free tier for new organisations, and Koyeb does
not offer a continuous free web service.

### Steps

1. Push this repository to GitHub.
2. In Render: **New → Blueprint**, select the repository. Render reads
   `render.yaml` and builds `Dockerfile.api`.
3. After the first deploy, copy the `https://<name>.onrender.com` URL.
4. Open `docs/live.html?api=https://<name>.onrender.com` and confirm
   `/health` and `/capabilities` respond.
5. Optionally set `apiBase` in `docs/assets/live-config.js` and publish the
   static site. Until then the site remains disconnected.

A local Docker run is equivalent:

```sh
docker build -f Dockerfile.api -t leaklens-api .
docker run --rm -p 8000:8000 leaklens-api
```

### Cold starts, busy and timeouts

The UI says “A free backend can take about a minute to wake up” while
connecting, and it uses a long health-check timeout. During a scan it shows a
real elapsed timer and request stages, but no invented percentage: the API does
not stream progress. If the single scan worker is busy, the API returns
`503 scan_busy` with `Retry-After`; if a scan exceeds the time budget it
returns `504 scan_timeout`. The UI maps both to an explicit message and a
retry action, never to a fake result.

## Environment variables

| Variable | Default | Notes |
|---|---|---|
| `LEAKLENS_PUBLIC_MAX_BYTES` | `4194304` (4 MiB) | Per-file limit, clamped 64 KiB–16 MiB |
| `LEAKLENS_PUBLIC_MAX_JSON_BYTES` | `524288` (512 KiB) | `/scan` request body |
| `LEAKLENS_PUBLIC_MAX_ROWS` | `5000` | Parsed rows, clamped 10–20,000 |
| `LEAKLENS_PUBLIC_MAX_COLUMNS` | `200` | Clamped 2–500 |
| `LEAKLENS_PUBLIC_MAX_CELLS` | `750000` | Rows × columns |
| `LEAKLENS_PUBLIC_MAX_UNCOMPRESSED_BYTES` | `25165824` (24 MiB) | XLSX ZIP expansion |
| `LEAKLENS_PUBLIC_TIMEOUT_SECONDS` | `30` | Wall-clock scan budget, 5–120 s |
| `LEAKLENS_PUBLIC_RATE_LIMIT` | `20` | POST requests per client per window |
| `LEAKLENS_PUBLIC_RATE_WINDOW` | `60` | Window in seconds |
| `LEAKLENS_PUBLIC_FORMATS` | `csv,json` | Comma-separated; enabling optional formats requires the parser extra |
| `LEAKLENS_ALLOWED_ORIGINS` | `https://eyadstein.github.io` | Comma-separated CORS origins |
| `LEAKLENS_ALLOW_LOCAL_ORIGINS` | `1` | Permit `http://localhost:*` during development |
| `LEAKLENS_TRUST_PROXY` | `0` | Trust `X-Forwarded-For` for rate limiting (set `1` behind Render) |
| `LEAKLENS_ENABLE_DOCS` | `0` | Serve `/docs` and `/openapi.json` |

CSV and JSON are available with the base dependencies. `.xlsx` needs
`pip install "leaklens-ml[excel]"`, and `.parquet` / `.feather` need
`pip install "leaklens-ml[parquet]"` or `[feather]`. The capabilities response
reports each format as `enabled`, `configured` and `installed`, and the UI
only offers formats the backend actually enables.

## Security model

Uploads are treated as hostile input:

* **Size first.** A request-body middleware rejects a declared `Content-Length`
  over the cap before multipart parsing, and counts chunked bodies as they
  stream. `/scan` has its own smaller JSON cap.
* **Content, not names.** The filename is sanitised (no paths, NUL or control
  characters). The claimed extension is checked against the configured
  allowlist, then the bytes are sniffed: UTF-8 CSV with a real header and row,
  JSON records/columns, ZIP magic plus workbook structure for XLSX, and the
  Parquet/Feather magic bytes. A `.csv` containing JSON, or executable content
  renamed `data.csv`, is rejected.
* **ZIP safety.** XLSX containers are rejected for path traversal, encrypted
  entries, too many entries, or expansion past the decompression limit.
* **Bounded parsing.** Rows, columns and cells are capped before detectors run.
  Plain CSV parsing exits early with `nrows`; the frame is validated again
  after parsing because a parser may expand a compact file.
* **Bounded memory.** Files are read in 64 KiB chunks into an in-memory buffer
  for one request, never written to disk, never persisted, never shared between
  requests. The upload handle is closed even when reading fails.
* **Serialised work.** One `ScanRunner` slot runs scans; overlapping requests
  get `503 scan_busy`. A timed-out worker keeps the slot until it actually
  finishes, so a timeout cannot silently pile up work.
* **Rate limiting.** A bounded sliding-window limiter caps expensive POSTs per
  client and evicts stale/forged keys instead of growing without limit.
* **Generic errors.** Parser exceptions, filesystem paths, stack traces and
  internal messages never reach clients; unexpected failures return a generic
  `500`. The response contains only the findings for that request.
* **No dangerous surfaces.** No `/predict`, no model deserialisation, no
  arbitrary file reads, no accounts, payments or cookies. There is no dataset
  storage to leak.
* **Headers and CORS.** `nosniff`, `DENY` framing, a restrictive CSP,
  `no-store`, a per-response request ID, HSTS behind TLS, and an origin
  allowlist with no credentials.

Limits are a denial-of-service control, not a privacy guarantee about the
network path. Use HTTPS for any public backend; the page refuses plain HTTP
except on localhost.

## Honest limitations

* The GitHub Pages build is static and disconnected by default.
* The Render free instance sleeps, cold-starts slowly and has 0.1 CPU; it is a
  demo/small-extract service, not a production scanning cluster.
* Progress is a real elapsed timer plus request-stage labels, not streamed
  server progress.
* Findings depend on the LeakLens version deployed; `/capabilities` and every
  result include the version.
* A browser cancel aborts the HTTP request but cannot kill work already running
  on the backend; the backend still enforces its timeout.
* The mobile layout, error states and offline fallback are covered by the site
  checks and the live-engine tests, but a real deployed backend is not exercised
  by CI.
