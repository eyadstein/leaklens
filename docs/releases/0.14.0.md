# LeakLens 0.14.0 — release notes

> **Status: prepared, not yet published.** This document describes the
> `0.14.0` release. The package metadata names `0.14.0`, but no tag, GitHub
> Release or PyPI publication has been made yet. `0.13.0` remains the latest
> published release until the release is authorised and executed.

## Overview

LeakLens 0.14.0 is the largest change since the project began. It turns the
scanner from a code-and-table leak detector into an auditable leakage review
workflow: findings now carry evidence and stable fingerprints, and you can
baseline, suppress, compare, export and verify a scan offline.

The release also adds optional engines for SQL lineage, train/test drift,
missingness, declared image splits, text/LLM contamination, deep-learning
training code and pipelines, plus an experimental AI layer. Every new engine is
opt-in, offline and additive: it does not change the trust score, the severity
of an existing finding, or the default exit code.

## Highlights

- **Evidence and fingerprints.** Every finding can explain itself with bounded,
  privacy-safe evidence, and a deterministic fingerprint that survives moved
  lines so CI can tell a new leak from an old one.
- **Baselines, suppressions and policy.** A versioned JSON baseline, exact
  fingerprint suppressions with a required reason, and a strict
  `.leaklens.toml` shared by the CLI and API.
- **Evidence graph and intelligence.** Findings are grouped into inspectable
  clusters, linked through existing evidence, and navigable as Mermaid, DOT or
  JSON, with confidence, root causes and remediation steps.
- **Audit provenance.** `--manifest` plus `leaklens verify` prove offline that an
  audit result and its declared inputs have not changed.
- **Optional specialist engines.** SQL lineage, drift, missingness, pipeline
  metadata, text/LLM contamination, deep-learning code and declared image
  splits, each behind an explicit flag and extra.
- **A local workspace and a hardened upload API.** A read-only interactive
  workspace for scans and dataset audits, and a separate FastAPI app designed
  for untrusted uploads.
- **A real product site.** A static site with a prerecorded demo, documentation
  and a live-scan page that connects only when you configure a backend.

## New capabilities

### Detection

- Partition inference for train/test/validation roles, including tuning on an
  arbitrarily named second return value.
- New checks for tuning before or on the full data, CV on the test partition,
  test-set reuse, and `GroupKFold` without `groups`.
- Target and frequency encoding, and feature selection, before the split.
- Temporal shuffle checks and a consolidated
  `future_target_feature_before_split` finding.
- Notebook out-of-order execution, feature overlap and near-duplicate overlap.
- A `no_stratify` advisory for splits that omit `stratify=`.
- Derived-variable dataflow tracking across multi-hop assignments.

## Important improvements

- **Detector precision.** `no_stratify`, `id_like` and `temporal_split_shuffle`
  are narrower and explain themselves better. Removed findings may appear as
  `resolved` in an existing baseline.
- **Baseline comparisons.** Evidence identity is location-neutral, and missing
  evidence is reported as `uncertain` rather than `resolved` when either scan is
  incomplete or the analysis context differs.
- **Measured scanner speed.** Local measurements on Windows and Python 3.14.3
  showed cold project scans about 60% faster and warm rescans about 89% faster;
  the detailed numbers are in [docs/PERFORMANCE.md](../PERFORMANCE.md).
- **Faster AI cold start.** Validated models load from a checked-in JSON
  artifact in about 1.7 ms instead of a 1.3 s fit, with bit-identical
  predictions. See [docs/AI_PERFORMANCE.md](../AI_PERFORMANCE.md).
- **Initialization.** `leaklens init` now pins the pre-commit snippet to the
  latest published tag instead of `main`.

## Bug fixes

- Quoted SQL identifiers and every set-operation branch are analysed correctly.
- Temporal splits no longer raise on mixed timezone-aware and naive timestamps.
- Detector-evidence links point at the correct finding.
- Corrupt images are counted as unreadable instead of crashing the audit.
- Non-UTF-8 baselines and workspace labels are handled cleanly.
- Release version metadata must agree across `pyproject.toml`, the runtime
  package, `CITATION.cff` and the changelog.
- The live page no longer throws on pages without an audit container.

## Security and reliability

- Path containment now normalises real paths and rejects NUL bytes; scans keep
  only regular files inside the target; baseline loading refuses non-regular
  files.
- Uploads are sniffed, size-limited, rate-limited and parsed from memory.
- Prompt-injection defenses and a versioned adversarial corpus guard the
  optional LLM layer. See [docs/PROMPT_INJECTION.md](../PROMPT_INJECTION.md).
- The release pipeline validates the tag, version, main ancestry and dispatch
  ref before checkout, validates wheel and sdist membership, keeps the SBOM
  outside `dist/`, and publishes last under the `pypi` environment using OIDC.
- CI declares read-only permissions, bounds every job, drops persisted checkout
  credentials, rebuilds the wheel from the sdist, and requires owner review for
  packaging-sensitive auto-merge paths.

## Compatibility and migration

**No public API function, CLI flag or exit code was removed.** Configuration
parsing for `.leaklens.toml` is new in this release. The release is additive,
with these user-visible refinements:

- **Detector output.** Some findings can disappear because the rules are more
  precise. An existing baseline will show them as `resolved`; this is not a
  regression.
- **Generated pre-commit configuration.** New `leaklens init` output pins a
  release tag. Existing files are untouched.
- **Report metadata.** JSON reports gain `$schema`, `evidence`, `fingerprint`
  and optional policy/graph sections. Reports written before this release still
  validate against `report-1`.
- **Fingerprints** are new in this release, so there is no older fingerprint
  schema to migrate from.
- **Python support** remains `>=3.10`. CI verifies 3.10, 3.11, 3.12 and 3.14;
  3.13 is not claimed as verified.

There are no deprecations in this release.

## Optional dependencies

Nothing in this release adds a mandatory runtime dependency. Optional features
fail with an `ImportError` that names the extra to install:

```sh
pip install "leaklens-ml[sql]"       # SQLGlot lineage
pip install "leaklens-ml[yaml]"      # DVC / YOLO YAML
pip install "leaklens-ml[images]"    # Pillow image auditing
pip install "leaklens-ml[app]"       # FastAPI, Uvicorn, Streamlit
pip install "leaklens-ml[api]"       # FastAPI, Uvicorn (public API)
pip install "leaklens-ml[parquet]"   # PyArrow
pip install "leaklens-ml[feather]"   # PyArrow
pip install "leaklens-ml[excel]"     # openpyxl
pip install "leaklens-ml[arena]"     # MLflow
```

## Known limitations

- Detection is heuristic and static; obfuscated or dynamically constructed
  patterns can be missed.
- The AI layer is experimental: hypotheses are capped at medium severity and
  never change the trust score or exit code.
- Python 3.13 is outside the CI matrix and is not claimed as verified.
- Benchmarks are deterministic regression guards, not estimates of real-world
  accuracy.
- `Dockerfile.api` (the optional live-scan deployment) uses a floating
  `python:3.11-slim` base; the default Compose image is pinned and runs
  non-root.

## Testing and verification

- The full test suite, the LeakLens self-scan and the labelled benchmarks run in
  CI on Python 3.10, 3.11, 3.12 and 3.14.
- Optional-extra jobs exercise SQL, the public API, the site and the spelling
  gate.
- Benchmarks are deterministic, labelled regression guards, not estimates of
  real-world accuracy. The AI holdout is reported as measured, including its
  false positives and its lower score than the authored locked test.
- No public backend is deployed by this repository, and the live page remains
  disconnected until a URL is configured.
