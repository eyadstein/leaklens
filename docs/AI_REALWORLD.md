# Phase 6 real-world evaluation

This report is generated by `python -m leaklens.bench_realworld`. It is an **external evaluation of the optional AI layer**, not a claim that AI improves the deterministic scanner, which remains authoritative.

## What was evaluated, and when

- Holdout: `phase6-realworld-holdout-v1` — 48 reviewed pipeline units from 12 public repositories.
- Labels: 24 leaky / 24 legitimate. Provenance: 4 verbatim excerpts, 44 reviewed reconstructions.
- Model: `leaklens-ai-p6` (leaklens-ai-p6-2026.11), 108 model features, threshold 0.50.
- Frozen manifest digest: `7fde39ce94d34ae7f05243163e2761d5410f4b3a01f9770eabc2a24ea45d5742`
- Digest matches the freeze commit: **yes** (expected `7fde39ce94d34ae7f05243163e2761d5410f4b3a01f9770eabc2a24ea45d5742`).

The corpus was frozen in commit `d3209e1` before the Phase 6 feature and model changes in this change set. Model family, calibration and threshold were selected on grouped development CV, validation and the scanner-benchmark transfer set. No holdout label, error or metric was used in this change set to choose features, calibration or threshold. The result below is reported as measured, including every mistake.

## Mistakes (all reported, none hidden)

### False positives

- **sklearn_scaling_for_plot_only** — `scikit-learn/scikit-learn` / `eda_only` (verbatim_excerpt, p=0.544). The full-frame fit is used only to draw a decision-boundary figure; no held-out score is computed from it, so there is no evaluation leak.
  - active signals: `fit_before_split`, `has_fit`, `target_reference`, `fit_without_split`, `has_fit_transform`
  - line 2 (`fit_before_split`): `X_plot_scaled = scaler.fit_transform(X_plot)`
  - source: https://github.com/scikit-learn/scikit-learn/blob/3c5e5effc5e11309209234507cb768c5fb38971b/examples/preprocessing/plot_scaling_importance.py
- **optuna_cross_val_objective** — `optuna/optuna-examples` / `tuning` (reconstructed_excerpt, p=0.749). There is no separate test partition in this example, so nothing is held out and nothing is contaminated. Tuning on the same CV folds does bias the reported score, but that is selection bias, not leakage.
  - active signals: `cv_on_full_data`, `cross_validation`
  - line 13 (`cv_on_full_data`): `score = sklearn.model_selection.cross_val_score(`
  - source: https://github.com/optuna/optuna-examples/blob/9450de9b8b042e396bb816fdbe7fb4b5227b3323/sklearn/sklearn_simple.py
- **xgboost_kfold_cv** — `dmlc/xgboost` / `cv_misuse` (reconstructed_excerpt, p=0.991). No preprocessing is fitted outside the folds and no row appears in both training and validation within a fold.
  - active signals: `cv_on_full_data`, `cross_validation`, `plain_kfold`, `target_in_assignment`, `has_shuffle`
  - line 6 (`cv_on_full_data`): `scores = cross_val_score(model, X, y, cv=cv)`
  - line 5 (`plain_kfold`): `cv = KFold(n_splits=5, shuffle=True, random_state=0)`
  - source: https://github.com/dmlc/xgboost/blob/f109cc0503aef1bcb21e7e0dc0b4e93a1ef9740a/demo/guide-python/cross_validation.py
- **xgboost_time_ordered_split** — `dmlc/xgboost` / `temporal` (reconstructed_excerpt, p=0.941). The split is positional on a time-sorted frame, so every test timestamp is later than every training timestamp.
  - active signals: `target_feature_risk`, `time_words`, `target_in_assignment`, `sort_values`, `train_only_marker`
  - line 4 (`time_words`): `ordered = df.sort_values("date")`
  - line 7 (`target_in_assignment`): `dtrain = xgb.DMatrix(train[features], label=train["sales"])`
  - line 6 (`train_only_marker`): `train, test = ordered.iloc[:cutoff], ordered.iloc[cutoff:]`
  - source: https://github.com/dmlc/xgboost/blob/f109cc0503aef1bcb21e7e0dc0b4e93a1ef9740a/demo/guide-python/cross_validation.py
- **lightgbm_train_valid_files** — `microsoft/LightGBM` / `preprocessing_order` (reconstructed_excerpt, p=0.896). Training and validation come from separate files and early stopping uses the validation file, keeping the final test file untouched.
  - active signals: `target_feature_risk`, `target_in_assignment`, `train_only_marker`
  - line 3 (`train_only_marker`): `df_train = pd.read_csv("regression.train", header=None, sep="\t")`
  - source: https://github.com/microsoft/LightGBM/blob/3ee03c26ba8c9e8ddc05fa8687717cae8a7d61d9/examples/python-guide/simple_example.py
- **catboost_pool_after_split** — `catboost/catboost` / `target_encoding` (reconstructed_excerpt, p=0.946). Target statistics are computed inside fit from the training pool only; the test pool is built after the split.
  - active signals: `target_feature_risk`, `log_split_position`, `fit_on_train_frame`, `has_fit`, `target_reference`
  - line 4 (`log_split_position`): `X_train, X_test, y_train, y_test = train_test_split(`

  - source: https://github.com/catboost/catboost/blob/ecf5e12040890db408ad73fda7b99da3dd394354/catboost/tutorials/classification/classification_tutorial.ipynb
- **catboost_ordered_time_split** — `catboost/catboost` / `temporal` (reconstructed_excerpt, p=0.548). The frame is ordered by timestamp and cut positionally, so training only contains earlier observations.

## What this does and does not show

- It shows transfer to 12 repositories that never appear in training, validation or the Phase 5 locked test.
- It does not estimate leak frequency in production code: the sample is small and skewed toward instructive public examples.
- 44 of 48 cases are reconstructions. They preserve control flow but are not verbatim upstream files.
- A 2026-11-06 audit resolved 16 of 23 cited paths at their pinned commits. Seven citations (13 cases, all reconstructions) point to renamed, moved or absent files; see `REALWORLD_CORPUS.md`. The corpus, digest and scores were left unchanged.
- One reviewer labelled every case; inter-rater agreement is unknown.
- Category and repository rows rest on 1-6 cases each.
- Calibration does not transfer: probabilities calibrated on 40 authored validation cases are over-confident on this holdout (Brier 0.115, ECE 0.126). Treat the probability as a ranking score, not a risk estimate.
- The public notebook smoke check has only eight scored units and belongs to the earlier scanner corpus; its interval is very wide.
